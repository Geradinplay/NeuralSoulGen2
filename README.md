# NeuralSoul — JavaFX GUI

Самостоятельная реализация предоставленного концепта: главная панель с Ниной и отдельное окно настроек. Maven, Java 17, JavaFX 17. Без Gradle, Docker и сторонних UI-библиотек.

## Запуск в IntelliJ IDEA

1. Распакуйте архив целиком.
2. Откройте `pom.xml` как Maven-проект.
3. Выберите JDK 17 или 21 в Project SDK и в Maven Runner.
4. Дождитесь загрузки Maven-зависимостей.
5. В окне Maven запустите **Plugins → javafx → javafx:run**.

Или в терминале в папке с `pom.xml`:

```sh
mvn clean javafx:run
```

В Windows можно запустить `run.bat`, если Maven установлен и доступен в PATH. При запуске из IDE используйте `com.neuralsoul.Launcher`, а не класс Application. Не требуется отдельно скачивать JavaFX SDK: Maven выберет библиотеки для текущей ОС.

## Что реализовано

- Главная: портрет из исходного концепта, меню, система, модели, быстрые действия, чаты, задачи, файлы, память.
- Чат: ввод, выбор модели и режима, асинхронный демонстрационный ответ, новый разговор.
- Настройки ресурсов: CPU / GPU 0 / GPU 1, переключатели, управление моделями, RAM / VRAM / потоки, таблица размещения.
- Настройки ресурсов сохраняются через Java Preferences после кнопки «Сохранить» и при закрытии приложения.
- Добавление файлов и каталогов через системные диалоги; файлы добавляются в список, их содержимое не передаётся в модель.
- Создание задач, добавление заметок в память. Эти списки и история чата живут в текущей сессии.
- Все пункты меню открываются. Для неподключённых модулей отображается их статус.
- Ctrl+N — новый чат, Ctrl+, — настройки, Enter — отправка.
- Прокрутка при уменьшении окна; размер обоих окон автоматически ограничивается рабочей областью текущего монитора (с учётом панели задач и логических координат JavaFX при масштабировании Windows). Минимум — 640×440, а на ещё меньшем рабочем столе он дополнительно уменьшается.

## Границы этой сборки

Это GUI, не полный AI-runtime. Показатели CPU/GPU, список моделей и задачи на главной — демонстрационные данные из концепта, а не сканирование оборудования. Карточки активных моделей — образец оформления и не означают, что модели запущены. Переключатели изменяют конфигурацию интерфейса и не выделяют реальную память GPU.

Настоящие LLM / STT / TTS, запуск агентов, поиск, захват экрана и управление компьютером не подключены. Общие разделы настроек содержат только доступные в GUI опции или описание неподключённого модуля. Перечень разрешённых устройств и выбранное размещение — независимые параметры; backend должен проверять доступность устройства и валидировать конфигурацию до запуска модели.

Изображение `concept.png` — предоставленный пользователем референс. `AvatarPane` отображает только область портрета через JavaFX viewport; интерфейс вокруг — настоящие JavaFX-контролы, не картинка. Для лучшей чёткости можно заменить портрет отдельным изображением высокого разрешения.

## Подключение к NeuralSoul

Реализуйте `AssistantBackend.send(message, model, mode)` и передайте свой объект вместо `new DemoBackend()` в `NeuralSoulApp`. Метод возвращает `CompletionStage<String>`; сетевые запросы выполняйте асинхронно. Контроллер переносит результат на JavaFX Application Thread. Ошибки показываются в чате. Результат предыдущего разговора не попадает в новый после Ctrl+N.

Свой монитор ресурсов подключайте к отображению `DashboardPage`, реальные списки моделей и устройств — к `AppState`. Не считайте флаг `enabled` подтверждением запущенного сервиса. Настройки GUI используют отдельный Preferences-узел `com/neuralsoul/desktop-concept` и не меняют конфигурацию существующего проекта NeuralSoul.

## Проверка

```sh
mvn test
mvn package
```

Тест запускает JavaFX без дисплея через тестовый Monocle, открывает страницы, отправляет сообщение через форму, проверяет ответ backend и сохранение настроек. Скриншоты создаются в `target/screenshots`. Monocle и JavaFX Swing имеют только test scope и не участвуют в обычном запуске приложения.

`mvn package` создаёт обычный JAR, не standalone EXE и не fat JAR. Для запуска используйте Maven/IDE; JDK и зависимости необходимы.

## Исправление адаптивности

- Окна открываются целиком внутри рабочей области экрана с отступом 12 логических пикселей. Размер рассчитывается по Stage (включая системный заголовок), а не только по Scene.
- Настройки открываются на мониторе родительского окна. При повторном открытии недоступная позиция корректируется; изменение списка мониторов пересчитывает границы.
- Главная панель перестраивается в одну колонку на узком окне. Меню сокращается до иконок с подсказками и прокручивается по высоте.
- Режимы чата и выбор модели переносятся на следующую строку. Поле ввода остаётся в нижней части окна.
- В узком окне настроек боковая навигация заменяется выпадающим списком; таблица размещения моделей переносит контролы по строкам. Кнопка сохранения остаётся доступной внизу.
- Тесты проверяют границы для рабочих областей 1366×728, 1024×728, 800×560, логических размеров при 150%/200% DPI, второго монитора с отрицательными координатами и отключённого монитора. GUI проверен при 640×480, настройки — при 800×560; ввод, отправка и сохранение внутри видимой области.
- Проверка выполнена на JavaFX в Linux/Monocle; нативное оформление и DPI Windows требуют проверки на целевой машине.
